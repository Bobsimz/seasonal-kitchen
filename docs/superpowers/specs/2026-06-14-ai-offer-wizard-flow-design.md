# AI 상품 등록 — 단계별 위저드 흐름 재설계

- 날짜: 2026-06-14
- 대상 화면: `frontend/app/(stack)/my/seller/offers/new/page.jsx` ("상품 등록" / AI로 생성하기)
- 범위: **프런트엔드(UI/클라이언트 로직)만.** API 계약·DB·백엔드 무변경.

## 목표

판매자가 상품을 올리는 흐름을 "조금 더 자연스럽게" 만든다. 지금은 모든 입력이 한 페이지에
세로로 쌓여 있고, AI 분석이 성공해야만 폼이 나타나는 등 흐름이 끊기는 지점이 있다.
이를 **한 화면에 한 가지 일만** 하는 5단계 위저드로 재구성하고, 흐름이 어색한 지점들을 함께 고친다.

## 현재 흐름의 문제점 (요약)

`page.jsx` 기준:

1. **게이팅 막다른 길** — AI 모드에서 분석이 성공(`analysis` truthy)해야만 폼·등록 버튼이 나타남
   (`:577-578`, `:723`). 분석 실패 시 토스트만 뜨고(`:172-174`) 폼이 영영 안 나타나 막힘. 재시도/직접입력 안내 없음.
2. **"checkpoint" 혼란** — 한글 화면에 영어 라벨(`:635`). 화면 칩은 고정 리스트(`:20`)인데,
   AI가 사진에서 뽑은 진짜 소구포인트(`analysis.checkpoints`: keyword+sentence 3개)는 화면에 안 보이고
   제출 시 `appealKeywords`로만 조용히 들어감(`:335`).
3. **설명 자동생성의 숨은 규칙** — 칩을 "정확히 2개" 골라야만 생성(`:96-98`). 1·3개째 무반응(`:94`),
   써둔 설명을 경고 없이 덮어씀, 재생성 버튼 없음.
4. **사진 모델 혼란** — 업로드 사진(`aiPhotos`)과 AI 생성 이미지(`photos`)가 별도 배열·별도 2줄로 표시
   (`:410`, `:470`). "대표" 배지는 업로드 첫 장에 붙지만(`:428`) 제출 땐 AI 생성본을 맨 앞에 넣어
   실제 대표가 됨(`:314-317`) → 배지와 실제 대표 불일치.
5. **버려지는 데이터** — AI가 주는 보관방법(`storageMethod`)은 제출 시 항상 `null`(`:332`)이고,
   추천 레시피(`recipe`)는 화면·저장 모두 미사용.

## 설계

### 전체 구조

단일 페이지를 유지하되, `step` 상태(1~5)로 한 단계씩 슬라이드/페이드 전환한다.
**라우트를 쪼개지 않는다** — 기존 업로드/분석/생성/제출 로직을 그대로 재사용하기 위함.

- 상단: 진행도 점(● 5개, 현재 단계 강조) + 단계 제목 + "n / 5".
- 하단(`BottomBar`): [← 이전](흰색 outline) / [다음 →]. 마지막 단계에서 [다음]은 [등록하기]로 바뀜.
- [다음]은 **해당 단계 필수 조건을 만족할 때만 활성화**(`disabled={!canNext()}`). 각 단계에 필수 안내/카운터를 함께 노출.
- 단계 전환은 좌우 슬라이드(또는 기존 `animate-fade-up` 재사용).

### 모드 통합 — "AI 도움받기" 토글

기존 상단 AI/직접 입력 **탭을 제거**하고, 1단계의 **"AI 도움받기 ✨" 토글**로 대체한다.

- 토글 ON(기본): 사진 업로드 시 자동 분석 → 2단계에서 결과 확인·자동채움.
- 토글 OFF: 분석 안 함. 2단계는 빈 입력 필드로, 사용자가 직접 채움.
- **상품 사진은 토글 상태와 무관하게 1장 이상 필수**(1단계 [다음] 게이팅).
- 제출 시 `isAi = aiAssist && !!analysis` (기존 `mode === 'ai' && !!analysis`와 동일 의미).
  `aiGenerated`·`appealKeywords`·`appealSentence` 세팅 로직은 그대로.

### 단계 구성 (5단계)

**1단계 · 상품 사진**
- "AI 도움받기 ✨" 토글.
- 통합 사진 스트립(아래 "사진 모델" 참조) + "＋" 추가 버튼.
- "✨ AI로 상품사진 만들기 · 배경을 깔끔하게" 버튼(효과 한 줄 설명 포함).
  - AI 생성본은 **대표 이미지를 바꾸지 않고 스트립 뒤(끝)에 추가**한다. 대표로 쓰려면 사용자가 "대표로" 버튼으로 지정.
- 토글 ON이고 사진이 추가되면 첫 장(대표) 자동 분석 시작.
- [다음] 게이팅: 모드 무관 **사진 ≥ 1장 필수**.

**2단계 · AI 분석 확인**
- "✨ AI가 이렇게 봤어요" 결과 카드(분석 중 스피너 → 결과). 자동채움임을 안내.
- 식재료명(필수), 카테고리(칩), 보관 방법(`storageMethod`) + 보관 안내(`storageTip`). 모두 수정 가능.
- **막다른 길 제거**: 분석 실패/지연이어도 이 단계는 항상 진입 가능. 실패 시 카드가
  "분석을 못했어요 — [다시 시도] 또는 아래에 직접 입력" 상태로 바뀜. 토글 OFF면 빈 입력.
- [다음] 게이팅: 식재료명 비어있지 않을 것.

**3단계 · 강조 & 설명**
- **강조 포인트**(기존 "checkpoint" 라벨 한글화) — **필수, 정확히 2개**:
  - "✨ AI 추천" 칩 그룹 = `analysis.checkpoints`의 keyword들(있을 때만 노출). 탭하면 설명 생성에 반영.
  - "빠른 배지" 칩 그룹 = 기존 고정 리스트(`당일배송`·`유기농` 등) → `tags`로 저장.
  - **AI 추천 + 빠른 배지를 합쳐 최대 2개**까지 선택(3개째 클릭은 안내 토스트로 차단). 분석 시 AI 추천 키워드 2개를 기본 선택.
  - 합계 2개여야 [다음] 활성화(`appealCount === 2`).
- **상품 설명**: **명시적 버튼**으로만 생성한다(기존의 "칩 정확히 2개" 자동 트리거 제거).
  - 빈 상태: "✨ AI로 설명 만들기". 내용이 있으면: "다시 생성 ⟳".
  - 버튼 클릭 시 선택된 강조 포인트를 keywords로 `generate-description` 호출.
  - 자동/암묵적 덮어쓰기는 없음 — 사용자가 버튼을 눌렀을 때만 생성 결과로 교체된다.
- 상품명(선택).

**4단계 · 가격 · 재고**
- 가격·단위(필수), 직거래 혜택 메시지(`price > 0`일 때), 재고 수량(선택).
- [다음] 게이팅: `price > 0`.

**5단계 · 확인 & 등록**
- 요약 카드: 대표 사진 썸네일 · 식재료명 · 가격/단위 · 선택한 강조 포인트 · 설명 일부.
- 요약 항목 탭 시 해당 단계로 이동해 수정(`step`만 변경).
- [등록하기] — 기존 `onSubmit` 재사용. 업로드 중이면 차단(기존 로직 유지).

### 사진 모델 통합

업로드 사진과 AI 생성 이미지를 **단일 정렬 배열**로 합친다.

- 아이템: `{ id, preview, url, uploading, file, source: 'upload' | 'ai' }`.
- 표시: 한 줄 스트립. **인덱스 0 = 대표**(배지 표시). AI 생성본은 "AI" 코너 태그.
- 대표 변경: 항목의 "대표로" 액션으로 해당 항목을 0번으로 이동(드래그까지는 범위 외).
- **AI 생성본은 자동으로 대표가 되지 않는다** — 스트립 끝에 추가되고, 대표는 사용자가 명시적으로 지정.
- 자동 분석 대상: 실제 분석에 사용된 사진 `id`를 별도 추적(`analyzedId`). 그 사진을 삭제할 때만 재분석.
- 분석 결과 자동채움은 **빈 필드만 채운다**(함수형 setState 가드) — 사용자가 수정한 값은 덮어쓰지 않음.
- 제출 매핑:
  - `photoUrls` = 배열 순서대로 `url`(대표가 맨 앞 — 배지와 일치).
  - `aiGeneratedPhotoUrls` = `source==='ai'` 항목의 `url`. **AI 도움받기 토글 상태와 무관**하게 사진 출처(provenance)로만 결정(토글을 끄더라도 AI 생성본 표식 유지).
  - `aiGenerated` = `분석 사용 || AI 생성 사진 존재` (토글이 아닌 실제 AI 산출물 기준).
  - `appealKeywords` = 선택된 강조 포인트(있으면), `appealSentence` = 분석이 있을 때의 설명.

이로써 문제 4(배지/실제 대표 불일치, 2줄 분리)가 함께 해결된다.

### storageMethod 저장

`CreateOfferRequest`·`ProducerOffer` 엔티티에 `storageMethod` 필드가 **이미 존재**하며,
현재 프런트가 `null`로 보내고 있을 뿐이다(`:332`). 분석 결과의 `storageMethod` 값을(2단계에서 수정 가능)
제출에 채워 넣는다. **백엔드 무변경.**

## 상태/구현 변경 (page.jsx)

- `mode`(tab) 제거 → `aiAssist`(boolean, 기본 true) + `step`(1..5) 추가.
- `aiPhotos`/`photos` 두 배열 → 단일 `photos` 배열(+`source` 필드)로 통합. 관련 핸들러
  (`onAiPhotosChange`/`onPhotosChange`/`removeAiPhoto`/`generateAiImage`)를 통합 모델 기준으로 정리.
- `toggleCheckpoint`의 "2개 선택 시 자동 생성" 제거 → 설명 생성은 버튼 핸들러로 분리.
- `runGenerateDescription` keywords 입력원: 선택된 강조 포인트(AI 추천 + 빠른 배지).
- 단계별 [다음] 검증 헬퍼 추가. 최종 `canSubmit`(식재료명 + price)·`onSubmit`은 유지.
- 진행도 표시·단계 네비게이션 UI 컴포넌트(파일 내 작은 컴포넌트로 분리).

## 범위 밖 (Out of scope)

- **추천 레시피 첨부** — offer에 레시피 저장 필드가 없어 Flyway 마이그레이션+엔티티/요청/응답+상세 UI가 필요.
  이번 UI 작업에서 제외. (분석 결과의 `recipe`는 계속 미사용.)
- 단계별 라우트 분리(별도 페이지). 단일 페이지 + step 상태로 처리.
- 사진 드래그 정렬(탭-투-대표로 대체).
- 백엔드/API/DB 변경 일체.

## 검증

- `frontend`에서 `npm run dev`로 흐름 수동 확인:
  - 사진 업로드 → 분석 진행/성공/**실패** 각각에서 막다른 길 없이 단계 진행 가능한지.
  - AI 도움받기 OFF 경로(직접 입력)로 끝까지 등록되는지.
  - 강조 포인트 선택 → 설명 생성/다시 생성, 기존 설명 보존.
  - 대표 배지가 실제 제출되는 대표 이미지와 일치하는지(AI 생성본 포함).
  - 등록 페이로드에 `storageMethod`·`tags`·`appealKeywords`·`photoUrls` 순서가 의도대로 들어가는지.
- 기존 lint 통과.
